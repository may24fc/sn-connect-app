# User Identity Display Task Tracker

## Current Status

The audit found two problems. (1) Views and APIs filled in made-up role, department, name or job title values when the real one was missing; the super-admin task detail showed "? ? Employee" for every assignee. (2) Photos loaded only where an API happened to read `users.avatar_url`.

Every audit finding is now fixed in the working tree, but nothing is committed yet. A second audit (2026-10-07) found 15 more cases outside tasks; all 15 are fixed and validated locally. An input-path audit then found fields nobody could enter (manager, internship/project supervisor, admin employee records, job titles); those now have inputs. Still open: running the department backfill (it needs a decision on which database to run it against), a manual browser check, and applying migrations `20261007000004` and `20261007000008` to production when the user asks for it.
