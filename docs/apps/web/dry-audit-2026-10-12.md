# DRY Audit — `apps/web` — 2026-10-12

> Implementation follow-up: [task tracker](../../features/dry-consolidation/task-tracker.md) and [optimization record](../../features/dry-consolidation/optimization.md). This report preserves its original read-only findings. On 2026-10-12, the user chose `admin` and `super_admin` as the only administrative roles, so B3's legacy-role redirect is skipped. B13's local type-generation path is fixed. B5's candidate-list claim needs re-evaluation: the current directory API excludes terminated rows by default, although grant-creation routes still need consistent status checks.

## Scope and method

- **Target:** `apps/web/src` (`app/` pages and API routes, `components/`, `hooks/`, `lib/`). About 193k lines in 922 files. Shared helpers in `packages/` were checked wherever `apps/web` bypasses or duplicates them.
- **Baseline:** commit `4bbee970` on `main`, plus the uncommitted working tree as it was on 2026-10-12.
- **Method:** the audit was split into five read-only passes: components, route pages, API routes, hooks, and lib. Each finding was confirmed by reading the code.
- **Counts:** counts come from grep. Multi-line constructions are slightly under-counted, so treat every count as approximate.
- **Re-checked claims:** the claims below were checked a second time before this report was written. They are marked ✔ where they appear.
  - Six access dialogs; only UHP excludes terminated users.
  - `toastMutation` and `createOptimisticMutation` have no callers.
  - 13 `readJson` copies.
  - `hooks/queries/useResources.ts` has no importers.
  - `STANDUP_ADMIN_ROLES` omits `super_admin`.
  - The DB-types generate path is broken.
  - `audit_logs` inserts use columns that don't exist.
  - The `/admin/probation` redirect.
  - Role-home mapping has no `hr`/`cos`/`ceo` case.
- **No code was changed.** This document is a findings list and a plan.

The main problem is not missing shared helpers. Most of the right helpers already exist: `lib/api-error.ts`, `lib/format.ts`, `lib/fx/rates.ts`, `lib/query-keys.ts`, `lib/mutation-helpers.ts`, `lib/audit.ts`, `lib/auth/role.ts`, `QueryStateScreen`, `ConfirmActionDialog`, `StatCard`, `PageHeader`, and `SkeletonTable`. They are bypassed by hand-written copies, and **many of those copies have already drifted apart**. Several of the drifts are live bugs; these are listed first.

## 2. Cross-cutting duplication themes

Severity is the amount of duplicated code multiplied by the likelihood of drift. Findings that the separate passes reported independently are merged here.

### 2.1 Auth and role resolution — **High (security)**

- **Domain auth helpers:** about 20 domain `_lib.ts` files each reimplement `getUser()`, then `app_metadata.db_role`, then a fallback to `users.role`.
  - Six of them are byte-identical functions named `getAuthedSupabase`: `api/{ai,announcements,jobs,notifications,resources,standups,wellness-bingo}/_lib.ts`.
  - The others use different names: `getCrmAuthedContext`, `getTaskAuthedContext`, `getUhpAuthedContext`, `lib/finance/auth.ts` `getFinanceContext`, and more.
- **How the copies drift:**
  - Whether the role is normalised (B6).
  - How a failed role lookup is handled: ignored in `uhp/_lib.ts:39`, turned into `null` in `revenue-forecast/_lib.ts:43`, or returned as a 401 elsewhere.
  - Two different result shapes.
  - Some helpers create an admin client before checking the role.
- **Inline auth in routes:** 76 routes call `auth.getUser()` themselves, and 74 of those import no `_lib`. The biggest groups are users (13), expenses (13), reports (7) and invoices (5). Seven expense routes reimplement `getFinanceContext`.
- **Role definitions:**
  - About 55 `*_ROLES` constants exist.
  - There are 109 inline role arrays, including `['admin','super_admin']` 48 times and the 5-role set 20 times.
  - There are 33 inline `role === 'admin' || role === 'super_admin'` checks.
  - `ADMIN_ROLES` means 2 roles in some files and 5 in others.
  - `hr`/`cos`/`ceo` are not in the DB `user_role` enum, so at least 25 lists carry dead values.
- **Role types:** they are declared in `lib/auth/role.ts`, `lib/roles.ts`, `lib/auth/user-bootstrap.ts:5`, `packages/database/src/enums.ts:17` and `packages/ui/src/layout/Sidebar.tsx:67`.
- **Role-to-home-page mapping** is defined in five places:
  - `getPostLoginRedirect`;
  - `useRequireAuth` (`contexts/AuthContext.tsx:586`);
  - `super-admin/payroll-approvals/layout.tsx:28`;
  - the inline expression `role === 'associate' ? '/associate/dashboard' : '/dashboard'`, which appears 5 times;
  - the mock-auth flag, which is repeated 4 times.
- **Client role guard:** `useRequireAuth` returns `user` even when the role is wrong; it only redirects later, in an effect. This is why `admin/reports/layout.tsx`, `super-admin/payroll-approvals/layout.tsx` and `admin/onboarding-setup/page.tsx` add their own redundant guards.

**Consolidate into:**
- `lib/auth/roles.ts`: one source for roles, merging `lib/roles.ts` and `lib/auth/role.ts`.
  - Type: `DbRole` derived from generated DB types.
  - Groups: `PLATFORM_ADMIN_ROLES`, `LEADERSHIP_ROLES`, `MEMBER_ROLES`.
  - Helpers: `hasAnyRole()` and `getRoleHomePath()`.
- `lib/api/auth.ts`: `getApiAuthContext({ withAdmin? })`, which always normalises the role and filters out soft-deleted users, plus `requireRole(ctx, roles)`. Each domain `_lib.ts` keeps only its own role group and grant table.
- New thin `_lib.ts` files for `users`, `expenses`, `reports`, `invoices`, `documents` and `directory`.
- `lib/auth/server-home.ts`: `resolveServerHome()`, used by `app/page.tsx` and the login page.
- `lib/auth/mock-auth.ts`: `isMockAuthEnabled()`.
- Change `useRequireAuth` so it returns `null` for disallowed roles, then delete the redundant layout guards.

### 2.3 Client-side fetch and error handling — **High**

Shared helpers exist in `lib/api-error.ts` (`ApiError`, `ensureOk`, `toApiError`, `getErrorMessage`) and `lib/mutation-helpers.ts` (`toastMutation`, `createToastMutationHandler`). They are barely used: there are about 10 call sites in hooks and 0 in pages and components (apart from `QueryStateScreen`), and `toastMutation` has 0 callers ✔.

- **Local fetch wrappers:** there are 18 in hooks.
  - 13 byte-identical copies of `readJson<T>` ✔: `useAiSpendingAccess`, `useAtsAccess`, `useCrmAccess`, `useMarketingAdSpendAccess`, `usePaTask*` (4), `useRevenueForecast*` (3), `useUhpAccess`, and others.
  - 5 `fetchJson`/`jsonFetch` variants: `useBingo`, `useChristmasTree`, `useGamification`, `useProjects`, `useProjectPool`.
  - `components/uhp/UhpClientDetailDialog.tsx:114` has another local `json<T>`.
- **Inline response checks:** there are 277 inline `!res.ok` checks across 105 files, written in four different styles.
  - 72 call `await response.json()` without `.catch`, so an HTML 5xx response throws a `SyntaxError`.
  - 73 throw away the server's error message.
  - `hooks/useResources.ts` mixes all three styles in one file.
- **Inline error messages:** there are about 150 inline `error instanceof Error ? error.message : '…'` expressions in `components/` and `app/`, and 51 hard-coded `'Please try again.'` fallbacks.
- **Lost status codes:** every plain `throw new Error` drops the HTTP status. Because of that, `QueryStateScreen` and `AnnouncementCommentsPanel`, which branch on `ApiError.status`, show a 403 or 404 as a generic failure.
- **Hand-written JSON requests:** there are 120 copies of `headers: { 'Content-Type': 'application/json' }` and 128 of `body: JSON.stringify`.

**Consolidate into:**
- `lib/api-client.ts`: `apiFetch<T>(url, { method, json, fallbackMessage, unwrapData })`, built on `ensureOk`.
- Use `getErrorMessage()` in toasts.
- Adopt `toastMutation` or delete it.
- Add a lint rule that bans `!response.ok` in `hooks/**`.

### 2.4 API route boilerplate — **Medium**

- **Error responses:** about 2,466 hand-built `NextResponse.json({ error }, { status })` calls.
  - `'Unauthorized'` 401: 312 times. `'Forbidden'` 403: 268. `'Internal server error'`: 378.
  - 155 copies of `{ error: auth.error }, { status: auth.status }`.
  - `lib/errors.ts` `apiError()` has **0 callers**. Its response shape `{ success, error: { code, … } }` also doesn't match what the client-side `toApiError` parses.
- **Try/catch:** 415 `catch (error)` blocks, and 232 copies of `console.error('Unexpected error in …')` followed by a 500.
- **Request bodies:** 142 bare `await request.json()` calls, so malformed JSON returns 500 instead of 400. Where routes do guard it, there are three different styles.
- **Zod failures:** about 170 copies of `{ error: 'Invalid request body', details: parsed.error.flatten() }`, using four different messages. Some routes return the issues under a different key that the client can't read: `issues` in `projects/intake` and `performance/drafts`, and `error.errors[0]` in `ai-expenses`.
- **Duplicated schemas:**
  - The `YYYY-MM-DD` regex appears in 15+ files.
  - `monthSchema` appears 4 times in `api/finance/*`.
  - `onboardingTaskInputSchema` appears twice, and update/delete task schemas are shared between onboarding and offboarding.
  - `yearQuerySchema` appears twice.
  - Six routes take JSON with no Zod validation at all: `departments`, `divisions`, `profile-change-requests` (×2), `resources/folders` and `onboarding/profile`.
- **Pagination:** 31 hand-written `page`/`pageSize` parses and 16 hand-written range/`totalPages` calculations (B10).
- **Postgres error mapping:** 19 hand-written checks for codes `2350x`, plus three `get*WriteErrorMessage` helpers that fall back to the raw Postgres `error.message`. There are 6 copies of the PGRST205 missing-table detector.
- **Archive/restore:** the handlers for announcements, resources and jobs are near-identical. None of them validate the UUID or write an audit entry.

**Consolidate into a `lib/api/` foundation:**
- `responses.ts`: `jsonError`, `unauthorized`, `forbidden`, `badRequest(zodError)`, `serverError`, `authFailure`.
- `handler.ts`: `withApiHandler(tag, fn)` and `parseJsonBody(req, schema)`.
- `pagination.ts`: `paginationQuerySchema` with a maximum of 100, `toRange`, `paginationMeta`.
- `db-errors.ts`: `mapPostgresWriteError`, which never echoes `message`, and `isMissingTableError`.
- `status-transition.ts`.
- `lib/schemas/common.ts`: `isoDateSchema`, `monthKeySchema`, `dateRangeQuerySchema`, `uuidParamSchema`.
- Either retire `lib/errors.ts` `apiError` or reshape it to match the client.
